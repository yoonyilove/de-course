# 환경설정 오류별 구조대

오류가 나도 전부 다시 설치하지 않습니다. 아래에서 **화면의 마지막 줄과 가장 비슷한 제목 하나**만 찾습니다.

## 1. `conda: command not found` 또는 `'conda'은(는) ... 아닙니다`

뜻: Miniconda가 없거나, 지금 연 창이 Miniconda를 모릅니다.

### Mac

1. 터미널을 닫고 다시 엽니다.
2. `conda --version`을 다시 실행합니다.
3. 계속 실패하면 Mac 안내서 4단계의 `/opt/miniconda3/bin/conda init zsh`를 실행합니다.

### Windows

1. 일반 명령 프롬프트를 닫습니다.
2. 시작 메뉴에서 `Anaconda Prompt (Miniconda3)`를 엽니다.
3. `conda --version`을 실행합니다.

## 2. `(base)`는 보이는데 `(de-course)`가 안 보입니다

뜻: Miniconda는 작동하지만 강의용 공구함을 아직 열지 않았습니다.

```bash
conda activate de-course
```

`EnvironmentNameNotFound`가 나오면 환경을 먼저 만듭니다.

```bash
conda create -n de-course python=3.12 -y
```

## 3. `No such file`, `cannot open requirements`, `경로를 찾을 수 없습니다`

뜻: 터미널이 강의 루트 폴더에 있지 않습니다.

Mac은 다음을 실행합니다.

```bash
pwd
ls
```

Windows는 다음을 실행합니다.

```bat
cd
dir
```

목록에 `week1`, `matchmaking_data`, `setup`, `requirements.txt`가 보여야 합니다. 보이지 않으면 플랫폼 안내서의 “강의 폴더로 이동” 단계로 돌아갑니다.

## 4. `ModuleNotFoundError`

뜻: 선택한 Python에 필요한 패키지가 없습니다.

1. 터미널 앞에 `(de-course)`가 있는지 봅니다.
2. 없으면 `conda activate de-course`를 실행합니다.
3. 강의 루트에서 패키지를 다시 설치합니다.

Mac:

```bash
python -m pip install -r requirements.txt
```

Windows:

```bat
python -m pip install -r requirements.txt
```

## 5. VS Code에 `Python (de-course)`가 없습니다

1. VS Code를 닫습니다.
2. 터미널 또는 Anaconda Prompt를 엽니다.
3. `conda activate de-course`를 실행합니다.
4. 아래 명령을 실행합니다.

```bash
python -m ipykernel install --user --name de-course --display-name "Python (de-course)"
```

5. VS Code를 다시 엽니다.
6. 노트북 오른쪽 위 `Select Kernel`을 다시 확인합니다.

## 6. 커널은 골랐는데 계속 로딩만 합니다

1. 30초 기다립니다.
2. 노트북 오른쪽 위 커널 이름을 누릅니다.
3. `Python (de-course)`를 다시 선택합니다.
4. VS Code 위 메뉴에서 `Developer: Reload Window`를 검색해 실행합니다.
5. 계속 실패하면 VS Code를 완전히 닫고 다시 엽니다.

## 7. `FileNotFoundError`

뜻: 노트북과 `data` 폴더의 상대 위치가 달라졌습니다.

1. 노트북만 따로 옮기지 않았는지 봅니다.
2. VS Code에서 강의 루트 폴더 전체를 열었는지 봅니다.
3. 노트북 첫 셀에서 현재 폴더를 확인합니다.

```python
from pathlib import Path
print(Path.cwd())
print(list(Path("data").glob("*.csv")))
```

1주차 노트북은 `week1` 폴더를 작업 위치로 사용해야 합니다.

## 8. `Permission denied` 또는 보안 경고

- 다운로드한 프로그램의 게시자가 Anaconda 또는 Microsoft인지 확인합니다.
- 출처가 맞을 때만 실행을 허용합니다.
- 강의자료는 `문서` 폴더처럼 본인이 쓸 수 있는 위치에 둡니다.
- 시스템 폴더나 다른 사용자 폴더에 강의자료를 두지 않습니다.
- `sudo`로 억지로 해결하지 않습니다.

## 9. 패키지 설치 중 인터넷·SSL 오류

1. 브라우저에서 일반 웹페이지가 열리는지 확인합니다.
2. 회사·학교 VPN이 켜져 있다면 담당 정책을 확인합니다.
3. 5분 후 같은 명령을 한 번 더 실행합니다.
4. 계속 실패하면 오류의 마지막 10줄을 복사합니다.

전체 Miniconda를 삭제하지 않습니다.

## 10. Surface가 ARM64입니다

처음 환경설정은 MacBook에서 완료합니다. VS Code는 ARM64용이 있지만, 공식 Miniconda의 Windows 시스템 요구사항은 64-bit x86을 대상으로 하므로 이 강의 패키지를 Surface ARM에서 즉시 동일하게 재현한다고 가정하지 않습니다.

Mac에서 성공한 뒤 Surface ARM 전용 환경은 별도 검증 과제로 진행합니다.

## 도움을 요청할 때 사진에 담을 것

다음 네 가지가 한 화면에 나오게 찍으면 빠르게 도울 수 있습니다.

1. 사용 중인 컴퓨터: Mac 또는 Surface
2. 터미널 앞부분의 `(de-course)` 여부
3. 입력한 명령어
4. 오류의 마지막 10줄

질문 예시:

> Mac에서 8단계까지 했고 `(de-course)`는 보입니다. 패키지 설치 마지막에 이 오류가 나왔습니다. 다음 한 단계만 알려줘.
