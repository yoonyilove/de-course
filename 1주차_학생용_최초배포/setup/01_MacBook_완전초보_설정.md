# MacBook 완전 초보 환경설정

> **이번 학생용 배포본에서의 이름 안내**
> 이 폴더의 이름은 `1주차_학생용_최초배포`입니다. 환경 점검은 아래 명령으로 실행합니다.
> `python setup/02_1주차_환경점검.py`
> 아래 본문에 남아 있는 예전 `course_materials` 또는 `1주차_학생용_수업패키지`라는 표현은
> 이전 배포본의 예시입니다. 이 배포본에서는 지금 안내한 폴더명과 점검 파일을 사용합니다.

목표: 자동 점검에서 `SETUP CHECK: PASS`를 확인하고, 1주차 1교시 학생용 노트북을 `Python (de-course)` 커널로 열어 첫 준비 셀을 실행합니다.

현재 강의 폴더가 있는 Mac은 Apple Silicon(`arm64`)으로 확인됐습니다.

## 준비물

- 인터넷 연결
- 약 30~60분
- 저장 공간 10GB 이상
- 강의 패키지 ZIP 파일
- Mac 로그인 암호

## 0단계: 지금은 아무 코드도 공부하지 않습니다

설치가 끝날 때까지 Python 문법과 슬라이드는 보지 않습니다. 오늘의 첫 번째 성공 표시는 `SETUP CHECK: PASS`입니다.

## 1단계: Mac 종류를 눈으로 확인합니다

1. 화면 왼쪽 위의 사과 모양 ``를 누릅니다.
2. `이 Mac에 관하여`를 누릅니다.
3. `칩` 또는 `프로세서` 줄을 찾습니다.
4. `Apple M1`, `M2`, `M3`, `M4`, `M5`처럼 보이면 Apple Silicon입니다.
5. 이 강의 폴더가 있는 현재 Mac은 이미 `arm64`로 확인됐으므로 Apple Silicon 파일을 선택합니다.

정상 기준: `Apple`과 `M`으로 시작하는 칩 이름이 보입니다.

## 2단계: Miniconda 설치 파일을 받습니다

1. Safari 또는 Chrome을 엽니다.
2. 주소창에 `https://docs.conda.io/miniconda.html`을 입력합니다.
3. Miniconda 다운로드 영역을 찾습니다.
4. `macOS Apple Silicon` 또는 `MacOSX-arm64`라고 적힌 설치 파일을 선택합니다.
5. 가능하면 `.pkg` 그래픽 설치 파일을 선택합니다.
6. 다운로드가 끝날 때까지 기다립니다.

주의: `Intel`이나 `x86_64` 파일을 선택하지 않습니다.

정상 기준: 다운로드 폴더에 이름에 `MacOSX-arm64`가 포함된 파일이 있습니다.

## 3단계: Miniconda를 설치합니다

1. 화면 아래 Dock에서 `Finder`를 누릅니다.
2. 왼쪽에서 `다운로드`를 누릅니다.
3. 방금 받은 Miniconda `.pkg` 파일을 두 번 누릅니다.
4. `계속`을 누릅니다.
5. 사용권 화면이 나오면 내용을 확인하고 `동의`를 누릅니다.
6. 설치 위치는 기본값을 사용합니다.
7. 설치 방식도 기본값을 사용합니다.
8. Mac 암호나 Touch ID를 요청하면 승인합니다.
9. `설치가 완료되었습니다`가 나올 때까지 기다립니다.
10. 설치 창을 닫습니다.

설치 중 `대상 선택`이 생략되거나 실패하면 `설치 위치 변경`을 눌러 현재 사용자 또는 Macintosh HD를 명시적으로 선택한 뒤 다시 진행합니다.

## 4단계: 터미널을 처음 엽니다

1. 키보드에서 `Command(⌘)`와 `Space`를 동시에 누릅니다.
2. 검색창에 `터미널`을 입력합니다.
3. 검은색 작은 창 모양의 `터미널`을 누릅니다.
4. 창이 열리면 마지막 줄을 한 번 클릭합니다.
5. 아래 명령을 복사해 붙여넣습니다.

```bash
conda --version
```

6. Enter를 누릅니다.

이 명령의 뜻: “방금 설치한 conda 프로그램이 실제로 작동한다면 버전 번호를 보여줘.”

왜 필요한가: 환경을 만들기 전에 설치 성공 여부를 가장 작은 질문으로 확인합니다. 여기서 실패하면 뒤의 명령도 작동하지 않으므로 먼저 고칩니다. `bash`라는 표시는 입력하지 않고 `conda --version`만 입력합니다.

정상 기준: `conda 26...`처럼 conda와 숫자가 보입니다. 숫자는 달라도 됩니다.

### `conda: command not found`가 나오는 경우

먼저 터미널을 완전히 닫고 다시 엽니다. 같은 명령을 한 번 더 실행합니다.

그래도 안 되면 아래 명령을 한 줄씩 시도합니다. 첫 번째가 성공하면 두 번째는 하지 않습니다.

```bash
/opt/miniconda3/bin/conda init zsh
```

```bash
~/miniconda3/bin/conda init zsh
```

성공한 뒤 터미널을 완전히 닫고 다시 열어 `conda --version`을 실행합니다.

## 5단계: 강의 ZIP을 풉니다

1. Finder에서 강의 ZIP 파일을 찾습니다.
2. ZIP 파일을 두 번 누릅니다.
3. 강사용 전체 자료라면 `course_materials`, 학생용 ZIP이라면 `1주차_학생용_최초배포` 폴더가 생겼는지 봅니다.
4. 폴더를 한 번 열어 봅니다.
5. 안에 `week1`, `matchmaking_data`, `setup` 폴더와 `requirements.txt` 파일이 있는지 확인합니다.
6. 이 폴더 전체를 `문서` 폴더로 옮깁니다.

정상 기준: 선택할 폴더 바로 안에 `week1`, `matchmaking_data`, `setup`, `requirements.txt`가 있습니다. 강사용 전체 프로젝트를 받았다면 먼저 `course_materials` 폴더 안으로 들어갑니다.

중요: `week1` 안의 노트북만 바탕화면으로 빼지 않습니다.

## 6단계: 터미널을 강의 폴더로 이동합니다

1. 터미널 창을 엽니다.
2. 아래처럼 `cd`와 한 칸의 공백까지만 입력합니다. 아직 Enter를 누르지 않습니다.

```text
cd 
```

3. Finder에서 바로 안에 `week1`, `matchmaking_data`, `setup`이 들어 있는 폴더를 찾습니다. 강사용 전체 자료는 `course_materials`, 학생용 자료는 `1주차_학생용_최초배포`입니다.
4. 그 폴더를 마우스로 잡아 터미널 창 안에 놓습니다.
5. 터미널에 긴 폴더 주소가 자동으로 입력됩니다.
6. 이제 Enter를 누릅니다.
7. 아래 명령을 실행합니다.

```bash
pwd
```

이 명령의 뜻: `pwd`는 현재 터미널이 서 있는 폴더의 전체 주소를 보여줍니다.

왜 필요한가: 패키지 목록과 데이터 파일은 현재 폴더를 기준으로 찾기 때문에, 잘못된 폴더에서 명령을 실행하면 파일이 있어도 없다고 나옵니다.

정상 기준: 마지막 부분이 `course_materials` 또는 `1주차_학생용_최초배포`입니다.

8. 아래 명령도 실행합니다.

```bash
ls
```

이 명령의 뜻: 현재 폴더 안에 들어 있는 파일과 하위 폴더 이름을 보여줍니다.

왜 필요한가: `week1`, `matchmaking_data`, `setup`, `requirements.txt`가 보이면 수업자료의 올바른 폴더에 들어온 것입니다.

정상 기준: 목록에 `week1`, `matchmaking_data`, `setup`, `requirements.txt`가 보입니다.

## 7단계: 수업 전용 환경을 만듭니다

아래 명령을 한 줄씩 실행합니다. 첫 명령은 몇 분 걸릴 수 있습니다.

```bash
conda create -n de-course python=3.12 -y
```

이 명령의 뜻: “`de-course`라는 강의 전용 공구함을 만들고 Python 3.12를 넣어줘. 중간 확인 질문에는 yes로 진행해.”

왜 필요한가: 다른 Python 프로젝트의 패키지와 섞이지 않게 3주 강의만의 독립된 환경을 만듭니다.

명령이 끝나고 다시 입력 줄이 나타나면 다음 명령을 실행합니다.

```bash
conda activate de-course
```

이 명령의 뜻: “지금부터 `de-course` 공구함 안의 Python을 사용해.”

왜 필요한가: 환경을 만들기만 해서는 아직 사용 중이 아닙니다. 활성화해야 이어지는 설치가 정확한 공구함 안에 들어갑니다.

정상 기준: 터미널 마지막 줄의 맨 앞에 `(de-course)`가 보입니다.

`(base)`만 보이면 아직 성공한 것이 아닙니다. `conda activate de-course`를 다시 실행합니다.

## 8단계: 수업에 필요한 패키지를 설치합니다

아직 터미널 앞에 `(de-course)`가 보이는지 확인합니다.

아래 명령을 실행합니다.

```bash
python -m pip install -r requirements.txt
```

이 명령의 뜻: “현재 선택한 Python으로 pip 설치 도구를 실행해서 지금 폴더의 `requirements.txt`에 적힌 패키지를 전부 설치해.”

왜 필요한가: NumPy, Pandas, Jupyter, FastAPI, Streamlit처럼 3주 동안 쓸 도구를 같은 목록으로 설치해 컴퓨터마다 차이를 줄입니다. `python -m pip`라고 쓰면 현재 활성화한 Python에 설치한다는 뜻이 분명해집니다.

인터넷 속도에 따라 5~20분 정도 걸릴 수 있습니다. 글자가 많이 움직이는 것은 정상입니다.

정상 기준:

- 마지막 부분에 빨간색 `ERROR`가 없습니다.
- 다시 `(de-course)`가 있는 입력 줄이 나타납니다.

## 9단계: 노트북용 커널 이름을 등록합니다

아래 명령을 한 줄로 실행합니다.

```bash
python -m ipykernel install --user --name de-course --display-name "Python (de-course)"
```

이 명령의 뜻: “VS Code의 Jupyter 노트북이 지금 만든 Python을 찾을 수 있도록 `Python (de-course)`라는 이름으로 등록해.”

왜 필요한가: 터미널의 Python 환경과 노트북 오른쪽 위의 커널 선택 목록은 자동으로 완전히 같아지지 않을 수 있습니다. 이 명령이 둘을 연결합니다.

정상 기준: `Installed kernelspec de-course`와 비슷한 문장이 보입니다.

## 10단계: 자동 상태 검사를 실행합니다

```bash
python setup/02_환경설정_상태확인.py
```

이 명령의 뜻: 현재 Python 버전, 환경 위치, 설치된 패키지, 강의 데이터와 노트북의 존재를 한꺼번에 읽기 전용으로 검사합니다.

왜 필요한가: 막연히 “설치된 것 같다”가 아니라 어떤 항목이 PASS이고 어떤 항목이 FAIL인지 분리하기 위해서입니다. 파일을 삭제하거나 설정을 바꾸지 않습니다.

정상 기준: 맨 마지막에 아래 문장이 나옵니다.

```text
SETUP CHECK: PASS
```

FAIL이 나오면 표시된 항목만 고칩니다. 전부 다시 설치하지 않습니다.

## 11단계: VS Code를 설치합니다

1. 브라우저에서 `https://code.visualstudio.com/Download`를 엽니다.
2. Mac용에서 `Apple silicon` 또는 `Universal`을 선택합니다.
3. 다운로드된 파일을 엽니다.
4. `Visual Studio Code` 아이콘을 `Applications` 폴더로 끌어 놓습니다.
5. Finder의 `응용 프로그램`에서 `Visual Studio Code`를 엽니다.
6. 처음 실행 경고가 나오면 출처가 Microsoft인지 확인한 뒤 `열기`를 누릅니다.

정상 기준: 왼쪽에 세로 아이콘이 있는 VS Code 창이 열립니다.

## 12단계: Python과 Jupyter 확장을 설치합니다

1. VS Code 왼쪽 세로줄에서 네모 블록 모양 `Extensions`를 누릅니다.
2. 검색창에 `Python`을 입력합니다.
3. 게시자가 `Microsoft`인 `Python` 확장을 찾습니다.
4. `Install`을 누릅니다.
5. 설치가 끝나면 검색창에 `Jupyter`를 입력합니다.
6. 게시자가 `Microsoft`인 `Jupyter` 확장을 찾습니다.
7. `Install`을 누릅니다.

정상 기준: 두 확장 모두 버튼이 `Uninstall` 또는 `Disable`로 바뀝니다.

## 13단계: 강의 폴더를 VS Code로 엽니다

1. VS Code 위 메뉴에서 `File`을 누릅니다.
2. `Open Folder...`를 누릅니다.
3. `문서`로 이동합니다.
4. 바로 안에 `week1`, `matchmaking_data`, `setup`이 있는 폴더를 한 번 선택합니다.
5. `Open`을 누릅니다.
6. 신뢰 여부를 묻는 창이 나오면 본인이 받은 강의자료인지 확인하고 신뢰 버튼을 누릅니다.

정상 기준: 왼쪽 파일 목록에 `week1`, `matchmaking_data`, `setup`이 보입니다.

## 14단계: 1주차 1교시 학생용 노트북을 엽니다

1. VS Code 왼쪽에서 `week1` 옆의 작은 화살표를 누릅니다.
2. `1주차_1교시_학생용_지적실험노트.ipynb`를 누릅니다. 파일이 바로 보이지 않으면 `lesson1_list_type_flow` 폴더 안을 봅니다.
3. 노트북 화면이 열릴 때까지 기다립니다.
4. 오른쪽 위에서 `Select Kernel` 또는 현재 Python 이름을 찾습니다.
5. 그것을 누릅니다.
6. 목록에서 `Python Environments...`를 누릅니다.
7. `Python (de-course)`를 선택합니다.

정상 기준: 오른쪽 위 커널 이름에 `de-course`가 보입니다.

## 15단계: 첫 준비 셀을 실행합니다

1. 첫 번째 Python 코드 셀의 왼쪽에 있는 삼각형 실행 버튼을 찾습니다.
2. 그 버튼을 한 번 누릅니다. 처음부터 `Run All`을 누르지 않습니다.
3. 처음 실행 권한을 묻는 창이 나오면 본인이 받은 강의자료인지 확인하고 실행합니다.
4. 코드 셀 왼쪽에 `[1]`처럼 실행 순서가 나타나는지 봅니다.
5. 빨간 오류 없이 준비된 회원 수나 첫 회원 정보가 출력되는지 확인합니다.

최종 정상 기준: 오른쪽 위 커널에 `de-course`가 보이고, 첫 준비 셀이 빨간 오류 없이 실행됩니다.

축하합니다. 여기까지가 환경설정입니다. 아직 Python을 이해하지 못해도 완전히 정상입니다.

## 다음 날 다시 시작하는 방법

1. VS Code를 엽니다.
2. 최근 폴더에서 강의 폴더를 엽니다.
3. 노트북의 오른쪽 위 커널이 `Python (de-course)`인지 확인합니다.
4. 아니라면 다시 선택합니다.
5. 터미널을 쓸 때는 먼저 `conda activate de-course`를 실행합니다.

> 아래 `내가 했던 질문들`은 사용자가 설치하면서 덧붙인 개인 학습 기록입니다. 당시의 옛 파일 경로와 FAIL 출력도 기록으로 남아 있습니다. 실제 설치와 점검은 위 0~15단계와 현재 `setup/02_환경설정_상태확인.py`를 기준으로 합니다.

## 내가 했던 질문들
**네, 전혀 문제없습니다.** 현재 위치한 폴더에 파일이 아무리 많거나 수시로 변경되어도 `conda create` 명령어를 실행하는 데 아무런 영향이 없습니다.

**왜 괜찮을까요?**

* **독립적인 중앙 관리 시스템:** `-n de-course` 옵션을 주면 가상환경은 현재 위치한 폴더(`pwd`)가 아니라, 미니콘다가 설치된 중앙 전용 경로(`~/miniconda3/envs/de-course`)에 생성됩니다.
* **폴더 오염 없음:** 현재 폴더에 가상환경 관련 시스템 파일이 새로 생겨서 수업자료를 어지럽히지 않습니다.

---

**터미널 작업의 실제 흐름**

1. **가상환경 생성 (`conda create -n de-course python=3.12 -y`)**
* 터미널 위치와 무관하게 컴퓨터 중앙 관리 영역에 독립된 파이썬 3.12 환경이 만들어집니다.


2. **가상환경 활성화 (`conda activate de-course`)**
* 터미널의 파이썬 실행 기준이 `de-course` 환경으로 전환됩니다. (터미널 프롬프트 앞에 `(de-course)`가 붙습니다.)


3. **수업자료 작업 진행**
* 활성화된 상태에서 해당 폴더의 코드를 실행하거나 필요한 패키지(`pip install pandas` 등)를 설치하면, 수업자료 폴더는 깨끗하게 유지되면서 가상환경에만 패키지가 차곡차곡 쌓입니다.



고민 없이 바로 해당 명령어를 실행하셔도 좋습니다.

가이드에서 굳이 **"폴더 이동 $\rightarrow$ `pwd`로 확인 $\rightarrow$ `conda create`"** 순서로 안내한 이유는 **Conda 때문이 아니라, 그 다음에 이어질 작업들의 편의성과 학습자 가이드 목적** 때문입니다.

강사/작성자 입장에서 그렇게 안내한 3가지 실무적 이유가 있습니다.

---

### 1. 터미널 조작 시 '길 잃음' 방지 (가장 중요한 이유)

터미널을 처음 쓰는 수강생은 현재 내가 어떤 폴더(경로)에 들어와 있는지 놓치기 매우 쉽습니다.
가상환경을 만들고 나서 바로 파이썬 코드나 주피터 노트북을 실행해야 하는데, 기본 홈 디렉토리(`~`)에서 헤매지 않도록 "일단 작업할 폴더로 이동해서 위치(`pwd`)부터 확실히 찍고 시작하자"는 가이드라인을 세워둔 것입니다.

### 2. 가상환경 활성화 직후 바로 주피터 노트북 / VS Code를 켜기 위해

보통 가상환경을 만들고 나면 바로 다음 단계로 넘어갑니다.

```bash
conda activate de-course
jupyter lab   # 또는 code . (VS Code 실행)

```

이때 미리 해당 수업 폴더로 이동해둔 상태여야, 주피터 노트북이나 VS Code를 켰을 때 **해당 폴더의 수업 파일들이 바로 루트(Root)로 예쁘게 열립니다.** 만약 홈 디렉토리에서 켰다면 주피터 노트북 안에서 다시 폴더를 찾아 들어가야 하는 번거로움이 생깁니다.

### 3. 폴더 안의 `requirements.txt` 설치 준비

보통 수업 자료 폴더 안에는 필요 라이브러리 목록이 적힌 `requirements.txt` 파일이 들어있는 경우가 많습니다.
가상환경을 만들고 활성화한 뒤, 바로 그 폴더 안에서 `pip install -r requirements.txt` 명령어를 치게 하려고 미리 폴더로 들어가게 안내한 것입니다.
