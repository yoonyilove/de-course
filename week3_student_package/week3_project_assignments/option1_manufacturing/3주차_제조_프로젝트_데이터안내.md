# 3주차 제조 프로젝트 데이터 안내

## 1·2주차와 연결

- 1주차: 설비 기본 정보가 한 행에 들어 있는 기준표를 정리했습니다.
- 2주차: 같은 ID가 반복되는 30일 로그를 대상별 한 행으로 요약했습니다.
- 3주차: 그 요약표를 API, DB, EDA, PCA, Streamlit이 함께 사용합니다.

## 시작 파일의 자료구조

- 파일: `data/manufacturing_equipment_summary.csv`
- 자료구조: Pandas DataFrame
- 크기: 240행×26열
- 한 행의 뜻: 설비 한 개
- 고유 ID: `equipment_id`
- 집단 비교 열: `plant`
- 교육용 상태 열: `maintenance_required`

## 프로젝트에서 새로 만드는 열

| 열 | 뜻 | 만들어지는 단계 |
|---|---|---|
| `pca_1` | 여러 입력 열을 요약한 첫 번째 좌표 | 노트북 Q2 |
| `pca_2` | 여러 입력 열을 요약한 두 번째 좌표 | 노트북 Q2 |
| `status_label` | True/False를 화면에서 읽기 쉬운 말로 표현 | 노트북 Q5 |

## 파일이 이동하는 순서

```text
manufacturing_equipment_summary.csv
→ DataFrame project_data
→ SQLite equipment_dashboard 테이블
→ manufacturing_dashboard_ready.csv
→ FastAPI /items
→ Streamlit 화면
```

## 주요 비교 숫자

- `alarm_count`: 30일 알람 수
- `quality_pass_rate`: 품질 통과율
- `maintenance_required`: 정비 확인 필요

> maintenance_required는 수업용 운영 라벨이며 실제 정비·안전 판단을 대신하지 않습니다.
